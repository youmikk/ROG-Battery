R Battery 隐私政策 / Privacy Policy

最后更新 / Last updated: 2026-11-23

中文

R Battery 是用于读取外设电量并调整支持的鼠标参数的 Windows 本地应用。日常电量读取和设备设置离线完成。仅在您主动提交反馈、补充说明或查看维护者回复时，应用才连接反馈服务。应用不包含后台遥测、广告或自动崩溃上报服务。

应用通过 Windows HID 和系统接口读取型号、连接状态、电量、固件及设备提供的序列号等信息，并在您操作时修改支持的设备设置。序列号等唯一标识用于本地识别设备和保存偏好，不会加入自动生成的反馈诊断。

本地数据

以下数据仅保存在您的电脑上：

  • 设置、语言、主题、托盘选择、设备名称和类型偏好。默认设置位于 %APPDATA%\rog-mouse-ctl\settings.ini。
  • 电量历史，用于绘制曲线和估算续航，默认位于 %LOCALAPPDATA%\rog-battery\history.tsv。
  • 设备状态缓存，默认位于 %LOCALAPPDATA%\rog-mouse-ctl\snapshot.cache。
  • 故障诊断与托盘日志，可能包含错误文本、设备状态或本地路径，不会自动上传。
  • 由您主动保存的设备配置备份，以及自定义存储位置的路径记录。
  • 通过应用提交的反馈历史、待确认的请求和回复密钥，使用 Windows DPAPI 加密保存在设置目录的 feedback-history.dat，由当前 Windows 用户保护。回复密钥不写入日志、诊断或公开议题。

诊断日志入口继续保留。独立设备报告窗口已移除，device-report 等命令行报告仍可使用；导出的报告不会自动上传。

主动反馈

您可以选择问题类型、设备、说明和最多三张截图，并决定是否附带诊断摘要。自动生成的诊断仅包含应用及系统版本、设备原始型号、VID/PID、类型、连接、电量、适配后端及接口与查询摘要，不复制序列号、设备路径、个人路径、用户别名、个人配置或日志原文。即使关闭诊断，提交仍包含应用版本、所选设备基本信息和您填写的内容。

配置了反馈服务的版本通过 HTTPS 将所选内容发送到 R Battery 自有反馈中继，由中继在 youmikk/ROG-Battery 仓库创建公开 GitHub 议题。问题描述、附带的诊断、截图和后续补充回复会公开展示。请勿在描述中填写您不希望公开的信息。

截图保存在反馈服务的私有 Cloudflare R2 存储桶，通过服务提供的公开图片链接显示在 GitHub 议题中。任何获得议题或图片链接的人都可以查看截图。图片不会重新编码，也不会自动清除画面中的个人内容或图片元数据，请在提交前自行检查。GitHub 和浏览器可能缓存公开内容。

回复密钥由客户端随机生成，用于查看和补充这份反馈。服务端只保存密钥的 HMAC 摘要，不将密钥写入 GitHub。反馈服务保留请求摘要、议题关联和去重记录，以处理网络中断和避免重复提交；限流使用 IP 地址的 HMAC 摘要，不在应用记录中保存原始 IP。承载服务的 Cloudflare 和 GitHub 会在提供网络服务时处理必要的连接信息，适用其各自的隐私政策。

未配置反馈服务的版本会明确提示，并提供复制内容及浏览器提交入口。浏览器提交由您自己的 GitHub 账号完成，截图需要手动添加，不会生成应用内反馈历史。应用不会转发到其他项目的反馈服务，也不会在后台自动检查回复。

保留与删除

启用开机自启时，绿色版使用当前用户的启动项，商店版使用 Windows StartupTask。您可以在设置中关闭，不需要管理员权限。

您可以随时删除本地数据。商店版数据由 Windows 管理；绿色版数据、自定义目录和导出的备份可能需要手动删除。删除本地反馈历史会移除回复密钥，无法再用该记录在应用内补充反馈；不会删除已公开的 GitHub 议题、评论或截图。

已提交及结果待确认的截图保留，以便查看议题；失败上传或明确被拒的提交，其已存截图在 24 小时后清理。需要删除公开反馈或截图时，请联系项目维护者；GitHub、浏览器和其他外部缓存不保证即时删除。若另外主动分享本地日志或备份，请先检查并移除序列号、个人路径等内容。

本政策更新时会修改上方日期。有关隐私的问题可通过 GitHub issues 联系。

English

R Battery is a local Windows application for monitoring peripheral batteries and changing supported mouse settings. Normal battery monitoring and device settings work offline. The app connects to the feedback service only when you submit feedback, add information, or check maintainer replies. It includes no background telemetry, advertising, or automatic crash-reporting service.

Through Windows HID and system interfaces, the app reads information such as model, connection status, battery level, firmware, and device-provided serial numbers. It changes supported settings when you request an operation. Unique identifiers such as serial numbers are used locally to distinguish devices and store preferences; they are not included in automatically generated feedback diagnostics.

Local data

The following data stays on your computer:

  • Settings, language, theme, tray selection, device names, and device type preferences. The default settings file is %APPDATA%\rog-mouse-ctl\settings.ini.
  • Battery history for charts and runtime estimates, at %LOCALAPPDATA%\rog-battery\history.tsv by default.
  • A device snapshot cache, at %LOCALAPPDATA%\rog-mouse-ctl\snapshot.cache by default.
  • Diagnostic and tray logs, which may contain error messages, device status, or local paths. They are not uploaded automatically.
  • Device configuration backups you explicitly save, and records of custom storage locations.
  • In-app feedback history, requests awaiting confirmation, and reply keys, encrypted with Windows DPAPI in feedback-history.dat in the settings directory and protected for the current Windows user. Reply keys are not written to logs, diagnostics, or public issues.

The diagnostic log entry remains available. The separate device report window is removed; command-line reports such as device-report remain available and are not uploaded automatically.

Feedback you choose to send

You can select an issue category and device, write a description, attach up to three screenshots, and choose whether to include a diagnostic summary. Automatically generated diagnostics contain only app and system versions, the original device model, VID/PID, type, connection, battery state, backend, and interface and query summaries. They do not copy serial numbers, device or personal paths, custom device aliases, personal settings, or raw logs. Even with diagnostics disabled, a submission includes the app version, basic details of the selected device, and the content you provide.

Builds with a configured feedback service send the selected content over HTTPS to R Battery's own relay, which creates a public GitHub issue in youmikk/ROG-Battery. Descriptions, included diagnostics, screenshots, and subsequent replies are public. Do not include information you do not wish to disclose.

Screenshots are stored in the feedback service's private Cloudflare R2 bucket and displayed in GitHub issues through public image links served by the relay. Anyone with an issue or image link can view the screenshot. Images are not re-encoded, and personal content in the picture or its metadata is not removed automatically. Review both before submitting. GitHub and browsers may cache public content.

The client generates a random reply key to access and add information to that feedback. The server stores only an HMAC digest of the key and never publishes it on GitHub. The relay retains request digests, issue associations, and deduplication records to recover interrupted submissions and avoid duplicates. Rate limits use an HMAC digest of the IP address; the application records do not retain the raw IP address. Cloudflare and GitHub process connection information needed to provide their services under their respective privacy policies.

If the feedback service is not configured, the app explains this and offers to copy the report and open browser submission. You submit using your own GitHub account and attach screenshots manually. Browser submissions do not create in-app feedback history. The app does not forward feedback to another project's service or check for replies automatically in the background.

Retention and deletion

When enabled, startup uses a per-user startup entry in the portable build or Windows StartupTask in the Store build. You can disable it in settings without administrator rights.

You can delete local data at any time. Windows manages Store app data. Portable data, custom directories, and exported backups may require manual removal. Deleting local feedback history removes its reply keys and the ability to use those records to reply through the app. It does not delete public GitHub issues, comments, or screenshots.

Screenshots for completed submissions and submissions awaiting confirmation are retained so issue links continue to work. Stored screenshots from failed uploads or explicitly rejected submissions are cleaned up after 24 hours. Contact the project maintainer to request removal of public feedback or screenshots; immediate deletion from GitHub, browsers, or other external caches cannot be guaranteed. Before separately sharing local logs or backups, remove serial numbers, personal paths, and other information you do not wish to disclose.

The date above changes when this policy is updated. For privacy questions, use GitHub issues.
